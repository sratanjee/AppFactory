# App Factory — CLAUDE.md

You are working in a mono-repo that ships one small, paid mobile app per day to iOS and Android. Read this fully before touching anything.

## Repo layout

```
factory/
  packages/
    core/            # shared Flutter package: adaptive UI layer, onboarding, paywall, analytics, storage, Shorebird wiring
    widgets_ios/     # Swift package: WidgetKit, Live Activities, App Intents, controls
    widgets_android/ # Kotlin module: Glance widgets, live notifications, QS tiles
  backend/           # ONE shared service: AI proxy, usage caps, RevenueCat webhooks. Never per-app.
  apps/
    <slug>/          # one Flutter app per spec, generated by `tools/scaffold`
  specs/             # daily specs, YYYY-MM-DD-<slug>.md, from SPEC_TEMPLATE.md
  tools/
    scaffold/        # deterministic app generator
    screenshots/     # Fastlane snapshot + Android screenshot lanes
  .claude/
    agents/          # planner, scaffolder, builder, native-builder, tester, reviewer, release
    commands/        # /build-app <spec>
    skills/          # flutter-factory, widgetkit-bridge, store-review-checklist, aso-copy
  DESIGN_GUIDE.md
  SPEC_TEMPLATE.md
```

## Non-negotiables

1. **The spec is the contract.** If it is missing a field, stop and write questions to `apps/<slug>/QUESTIONS.md`. Do not invent product decisions.
2. **Local-first.** No accounts, no login, no backend unless the spec's §4 says so. Storage is Drift/SQLite via `core/storage`.
3. **Paywall before use.** Every app calls `core/paywall` at the placement in spec §6. Purchases go through RevenueCat. No app ships without a working sandbox purchase on both platforms.
4. **Platform-adaptive UI only.** Screens use `core/adaptive`. Never import `package:flutter/material.dart` or `cupertino.dart` directly in `apps/`. Follow `DESIGN_GUIDE.md`.
5. **Native surfaces are native.** Widgets, Live Activities, Glance, tiles, App Intents live in `widgets_ios` and `widgets_android`, fed through `core/widget_bridge`.
6. **No placeholders.** Pre-commit blocks `TODO`, `lorem`, `FIXME`, `placeholder`, `John Doe`, `example.com`.
7. **Shorebird on every app.** Code push is how we fix a fleet without thirty store reviews.
8. **One accent, one job, no scope creep.** Anything not in the spec goes in `REVIEW.md` under "Not built", not in the code.
9. **Sibling apps must not look like a series.** Different glyph, accent, onboarding copy, and screenshot story from every other app in the same factory category. Reviewer checks against `apps/*/store/`.
10. **Humans submit to stores.** The pipeline stops at TestFlight and Play internal testing.

## Pipeline

`/build-app specs/<file>.md` runs these in order. Each agent has its own prompt in `.claude/agents/` and a restricted tool set.

| Agent | Input | Output | Can edit |
|---|---|---|---|
| planner | spec, this file, DESIGN_GUIDE | `apps/<slug>/PLAN.md` or `QUESTIONS.md` (stop) | plan files only |
| scaffolder | spec | `apps/<slug>/` from template, bundle IDs, RevenueCat + Shorebird entries, store metadata stubs | new app dir |
| builder | PLAN.md | screens, data model, tests; runs `flutter analyze` + unit tests after each task | `apps/<slug>/lib`, `test` |
| native-builder | spec §5 | Swift/Kotlin widget targets wired to the bridge | `ios/`, `android/`, widget packages |
| tester | app | integration tests on iOS Simulator + Android emulator; screenshots per screen/device/theme/text-size to `apps/<slug>/qa/` | `integration_test/`, `qa/` |
| reviewer | spec, diff, qa screenshots | pass, or task list back to builder (max 3 rounds) | `REVIEW.md` only |
| release | passing app | version bump, store screenshots, ASO copy, TestFlight + Play internal upload via Codemagic | `store/`, `pubspec.yaml`, CI |

The reviewer always runs in a fresh context. It reads `DESIGN_GUIDE.md` and looks at the screenshots before reading code.

## Commands

```bash
flutter analyze                       # must be clean
flutter test                          # unit
flutter test integration_test -d <id> # integration, per platform
tools/screenshots/run.sh <slug>       # all devices, light/dark, 100%/200% text
tools/scaffold/new.sh <spec>          # new app from spec
```

Simulator/emulator IDs are in `tools/devices.json`. Never hard-code them.

## Conventions

- Dart: `dart format`, `very_good_analysis` lint set. Riverpod for state. `go_router` for navigation, with platform-correct transitions provided by `core/adaptive`.
- File names snake_case; one widget per file for screens.
- Strings in `lib/l10n/` from day one, English only unless spec says otherwise.
- Analytics events: `onboarding_step`, `paywall_view`, `paywall_purchase`, `core_action`, `widget_added`. Nothing else without a reason in PLAN.md.
- Commits: `<slug>: <what>` on branch `app/<slug>`. Squash-merge to `main` only after reviewer pass.

## What "done" looks like at 7 a.m.

- TestFlight build installed on the founder's phone
- Play internal testing build available
- `apps/<slug>/REVIEW.md` with: built / cut / open questions / screenshot links
- `apps/<slug>/store/` with copy and screenshots for both stores
- CI green on `app/<slug>`

## When in doubt

Ship less. A three-screen app that purchases correctly beats a six-screen app with one broken flow. Remove one thing from every screen before sign-off.
